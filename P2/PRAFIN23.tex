\subsection{Decode phase}

When developing an instruction decoder it is very common to use a Binary Decision Tree, a structure
based on a sequential decision process. This technique is very useful when the instructions's
opcodes to decode are completely arbitrary, with no common pattern between them and their assigned
ID. Luckily, this is not the case for the instruction set of the HAL9000, shown in
Table \ref{table:halinstructions}, as each instruction's ID is encoded within its opcode (with some
exceptions).

In order to take advantage of this pattern, we must separate the instruction set into two groups and
an exception.

\noindent\textbf{Group 0} \\
Instructions with IDs from 0 to 6 follow the pattern:
\begin{equation*}
	\mathbf{0x_3x_2x_1k_{12}k_{11}k_{10}k_9k_8k_7k_6k_5k_4k_3k_2k_1}
\end{equation*}
where $\mathbf{x_{1 \ldots 3}}$ encode the instruction's ID as an unsigned binary number and
$\mathbf{k_{1 \ldots 12}}$ encode the rest of the instruction. This scenario is very easy to resolve
as the only thing needed tp obtain the ID is to logically shift right the whole instruction by 12:
\begin{equation*}
	\mathbf{0000000000000x_3x_2x_1}
\end{equation*}

\noindent\textbf{Group 1} \\
Instructions with IDs from 8 to 14 follow the pattern:
\begin{equation*}
	\mathbf{1x_4x_3x_2x_1k_{11}k_{10}k_9k_8k_7k_6k_5k_4k_3k_2k_1}
\end{equation*}
where $\mathbf{x_{1 \ldots 4}}$ encode the instruction's ID as an unsigned binary number and
$\mathbf{k_{1 \ldots 11}}$ encode the rest of the instruction. This scenario may be resolved by
setting the MSb to 0 and logically shifting right the whole instructin by 11:
\begin{equation*}
	\mathbf{000000000000x_4x_3x_2x_1}
\end{equation*}
