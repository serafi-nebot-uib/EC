\section{Introduction}
This assignment consists of developing an emulator for the HAL9000 computer (guest) on the Motorola
68000 (host) using assembly language. The guest program, registers and memory are contained within
the emulator's memory. The emulator's life cycle is divided into three phases:
fetch, where the next guest computer instruction to execute is retrieved from guest program memory,
decode, where the guest computer instruction to execute is identified and execution, where the
behaviour of the guest computer instruction to execute is emulated on the host computer.

\subsection{What is an emulator?}
An emulator allows a computer system to run software designed for a completely different computer
system. This can be achieved by \emph{imitating} the execution of each individual instruction from the
guest computer on the host computer. But this imitation comes at a cost, execution of a single
emulated instruction usually implicates the execution of many host instructions. Consequently, the emulated
software will, typically, run slower on the emulated computer than on the original computer.

\section{Fetch phase}
The fetch phase of the H9K is fairly simple and can be described by the following
precedure:
\begin{enumerate}
	\item Load 16 bits from ememory pointed by $\mathbf{EPC}$ into $\mathbf{EIR}$
	\item Increase $\mathbf{EPC}$ by 1
\end{enumerate}
We have to take into account the fact that each memory cell of the H9K, unlike the M68K , holds 16
bits, instead of 8. This is why the $\mathbf{EPC}$ register is incremented by 1
instead of 2. Therefore, in order to load the instruction from ememory directly, the value of
$\mathbf{EPC}$ has to be multiplied by 2 ($16 / 8 = 2$).

So, the updated version of the previous procedure is:
\begin{enumerate}
	\item Load 16 bits from ememory pointed by $\mathbf{EPC} \cdot 2$ into $\mathbf{EIR}$
	\item Increase $\mathbf{EPC}$ by 1
\end{enumerate}

This procedure can be implemented with the following M68K assembly code:
\begin{lstlisting}[style=customasm, caption={HAL9000 emulator fetch phase code}, label={code:fetchcode}]
MOVE.W EPC, D1
MULU #2, D1		; multiply address by 2 (each position contains 2 Bytes)
MOVEA.W D1, A0
MOVE.W EMEM(A0), EIR	; load current instruction to EIR
ADDQ.W #1, EPC		; increase EPC by 1 after fetch
\end{lstlisting}

\section{Decode phase}
\subsection{Decode phase introduction}

When developing an instruction decoder it is very common to use a Binary Decision Tree, a structure
based on a sequential decision process. This technique is very useful when the instructions'
opcodes to decode are completely arbitrary, with no common pattern between them and their assigned
ID. Luckily, this is not the case for the instruction set of the H9K, shown in Table
\ref{table:h9kinstructions}, as each instruction's ID is encoded within its opcode (with some
exceptions).

In order to take advantage of this pattern, let's separate the H9K instruction set into two groups and
an exception.

\noindent\textbf{Group 0} \\
Instructions with ID from 0 to 6 follow the pattern:
\begin{equation*}
	\mathbf{0x_3x_2x_1k_{12}k_{11}k_{10}k_9k_8k_7k_6k_5k_4k_3k_2k_1}
\end{equation*}
where $\mathbf{x_{1 \ldots 3}}$ encode the instruction's ID as an unsigned binary number and
$\mathbf{k_{1 \ldots 12}}$ encode the rest of the instruction. This scenario is very easy to resolve
as the only thing needed to obtain the ID is to logically shift right the whole instruction by 12
bits:
\begin{equation*}
	\mathbf{0000000000000x_3x_2x_1}
\end{equation*}

\noindent\textbf{Group 1} \\
Instructions with ID from 8 to 14 follow the pattern:
\begin{equation*}
	\mathbf{1x_4x_3x_2x_1k_{11}k_{10}k_9k_8k_7k_6k_5k_4k_3k_2k_1}
\end{equation*}
where $\mathbf{x_{1 \ldots 4}}$ encode the instruction's ID as an unsigned binary number and
$\mathbf{k_{1 \ldots 11}}$ encode the rest of the instruction. This scenario may be resolved by
setting the MSb to 0 and logically shifting right the whole instruction by 11 bits:
\begin{equation*}
	\mathbf{000000000000x_4x_3x_2x_1}
\end{equation*}

\noindent\textbf{The exception} \\
Instruction with ID 7 is the only one which does not follow any pattern:
\begin{equation*}
	\mathbf{10k_{14}k_{13}k_{12}k_{11}k_{10}k_9k_8k_7k_6k_5k_4k_3k_2k_1}
\end{equation*}
where the two MSb ($\mathbf{10}$) is the instruction's opcode and $\mathbf{k_{1 \ldots 14}}$ encode
the rest of the instruction. This scenario may be resolved by checking the two MSb and hardcoding
the ID.

\subsection{Decode phase implementation}
Due to the fact that the H9K instructions can be divided into two groups, a one-level Binary Decision
Tree has been implemented in order to treat each group differently.

The decode algorithm has been implemented in the following manner:
\begin{enumerate}
	\item If the MSb is equal to $\mathbf{0}$ then the instruction is in \textbf{Group 0}. Go to
		step 6.
	\item If the MSb is equal to $\mathbf{1}$ then the instruction is in \textbf{Group 1} or
		\textbf{The exception}.
	\item Shift left by 1 bit to make the instruction's opcode the same size as \textbf{Group 0}'s.
	\item If the MSb is equal to $\mathbf{1}$ then the instruction is in \textbf{Group 1}. Got to
		step 6.
	\item Replace the instruction with $\mathbf{0111000000000000}$ (instruction is \textbf{The
		exception}; replace opcode with a hardcoded value).
	\item Shift right 12 bits to obtain the instruction's opcode.
\end{enumerate}
The decode algorithm can be translated into the following M68K subroutine assembly code:
\begin{lstlisting}[style=customasm, caption={HAL9000 instruction decoder subroutine}, label={code:h9kdecoder}]
DECOD:
	MOVE.L D0, -(SP)		; save current value of D0
	MOVE.W 8(SP), D0		; load instruction
	BTST.L #15, D0
	BEQ.S DECOD_END			; if bit 15 = 0 jump to end
	LSL.W #1, D0			; logically shift left to "normalize"
					; 5 bit opcode to 4 bit opcode
	BTST.L #15, D0
	BNE.S DECOD_END			; if bit 15 = 1 jump to end
	MOVE.W #%0111000000000000, D0	; if bit 15 = 0 then instruction = EXIT
DECOD_END:
	; logically shift right the four MSb to the four LSb
	LSR.W #8, D0
	LSR.W #4, D0
	MOVE.W D0, 10(SP)		; save instruction ID to reserved space
	MOVE.L (SP)+, D0		; restore value of D0
	RTS
\end{lstlisting}

Which can be used along with the following M68K assembly code to decode the instruction in
$\mathbf{ESR}$:
\begin{lstlisting}[style=customasm, caption={HAL9000 instruction decoder subroutine call}, label={code:h9kdecodercall}]
SUBQ.W #2, SP		; reserve 1 word for instruction id
MOVE.W EIR, -(SP)	; pass instruction to decode
JSR DECOD
ADDQ.W #2, SP		; pop instruction to decode from stack
MOVE.W (SP)+, D1	; retrieve instruction's id
\end{lstlisting}

\section{Execution phase}
\subsection{Instruction selection}
After the decode phase, we know which einstruction to execute. More specifically, we know the ID of
the einstruction to execute. In order to execute the correct einstruction, a jump list has been used
to jump to the appropiate einstruction's implementation code:
\begin{lstlisting}[style=customasm, caption={HAL9000 instruction execution jump list}, label={code:h9kexcjmplst}]
	; assuming D1 contains the einstruction's id
	MULU #6, D1 ; multiply by 6 as each JMP instruction occupies 6 Bytes
	MOVEA.L D1, A1
	JMP JMPLIST(A1)
JMPLIST:
	JMP ELOA
	JMP ESTO
	JMP ELOIP
	JMP ESTIP
	JMP EGOI
	JMP EGOZ
	JMP EGON
	JMP EEXIT
	JMP ECOPY
	JMP EADD
	JMP ESUB
	JMP EAND
	JMP ESET
	JMP EADQ
	JMP ELSH
\end{lstlisting}

$\mathbf{JMPLIST}$ is an ordered list of $\mathbf{JMP}$ instructions with the corresponding
einstruction's labels. For instance, if the current einstruction to execute is $\mathbf{EADD}$, the
value of $\mathbf{D1}$ will be 9, which is $\mathbf{EADD}$'s ID (see Table
\ref{table:h9kinstructions}). Then, $\mathbf{D1}$ will be multiplied by 6 to point to the 9'th entry
of the $\mathbf{JMPLIST}$. Finally, using the value of $\mathbf{D1}$ to index $\mathbf{JMPLIST}$,
execution is redirected to the 9'th entry of $\mathbf{JMPLIST}$ and, from there, redirected to the
implementation of $\mathbf{EADD}$'s execution.

\subsection{Instruction parsing}
Before an einstruction can be executed, the operands, which are encoded within the einstruction,
must be retrieved. For this, the einstruction is shifted right the necessary amount so that the operand
is aligned to the LSb and then masked with an AND operation to obtain the operand value.

For example, the $\mathbf{k}$ operand of the $\mathbf{ESET}$ instruction can be parsed with the
following steps\footnote{The \texttt{>>} operator refers to the logic shift right operation and the
	\texttt{\&} operator refers to the logic AND operation}:
\begin{enumerate}
	\item \verb|0b11100kkkkkkkkccc >> 3 = 0b00011100kkkkkkkk|
	\item \verb|0b00011100kkkkkkkk & 7 = 0b00000000kkkkkkkk|
\end{enumerate}

\subsection{Instruction implementation}
The following is a procedure used to describe the generic implementation of einstructions:
\begin{enumerate}[label*=\arabic*.]
	\item Load einstruction's operands into $\mathbf{D2}$, $\mathbf{D3}$ and $\mathbf{D4}$,
		respectively.\footnote{Even though einstructions can have up to 3 operands, not all of them
		have 3 operands. Registers $\mathbf{D2}$, $\mathbf{D3}$ and $\mathbf{D4}$ are \emph{reserved} to store the first, second and
	third oprand, respectively.}
	\item Emulate einstruction's execution.
	\begin{enumerate}[label*=\arabic*.]
		\item Load data from eregisters or ememory, if necessary.
		\item Calculate result, if necessary.
		\item Store result to eregisters or ememory, if necessary.
		\item Update eregisters, if necessary.
	\end{enumerate}
	\item Update the corresponding $\mathbf{ESR}$ flags.\footnote{Not all einstructions update all
		eflags and some don't update any.}
	\item Jump to fetch phase.\footnote{$\mathbf{EXIT}$ is the only
		exception, as it stops execution.}
\end{enumerate}
\vfill
\pagebreak
For example, the $\mathbf{ELOIP}$ implementation performs all actions described above:
\begin{lstlisting}[style=customasm, caption={HAL9000 LOIP instruction implementation}, label={code:h9eloipimpl}]
LOIP:
	CLR.L D4

	; load Xb operand to D2
	MOVE.W EIR, D2
	LSR.W #4, D2
	ANDI.W #%111, D2

	; load Ti operand to D3
	MOVE.W EIR, D3
	ANDI.W #%1, D3

	; get value of Xb
	MOVE.W D2, -(SP)
	JSR RGET
	MOVE.W (SP)+, D4

	; set value at address Xb to Ti (Ti <- [[Xb]])
	MOVE.W D3, -(SP)
	MOVE.L D4, D5
	MULU.W #2, D5
	MOVEA.L D5, A2
	MOVE.W EMEM(A2), -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; set Xb to Xb + 1 (Xb <- [Xb] + 1)
	ADDQ.W #1, D4
	MOVE.W D2, -(SP)
	MOVE.W D4, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; set flags NZ from ESR
	MOVE.W #%011, -(SP)
	MOVE.L D4, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
\end{lstlisting}

\section{Tests}
\subsection{Individual einstructions}
The purpose of these tests is to validate the implementation of each indivual einstruction.
Specifically, each einstruction test checks both its behaviour during execution (einstruction
produces the expected result) and that the eflags are updated as expected. This test has been done
for all einstructions. Refer to Table \ref{table:h9kinstructions} for a detailed overview of
expected behaviour for each einstruction.

\textbf{Example test (ESUB)} \\
The following test code (displayed in Listing \ref{code:h9ktestsub}) is used to
showcase the individual einstruction test procedure.

It first performs the operation $-50 - (-100)$ and stores the
result into $\mathbf{ET0}$ and then performs the operation $0 - 0$ and stores the result in
$\mathbf{ET1}$. The first $\mathbf{ESUB}$ einstruction is used to check that the order of the
subtract operation is perfomed as expected: second operand - first operand. The second
$\mathbf{ESUB}$ einstruction is used to check the special case of $0 - 0$, which obviously, its
result should be 0 and, consequently, the $\mathbf{Z}$ eflag from $\mathbf{ESR}$ should be set to 1 but, not so obviously, the
$\mathbf{C}$ eflag from $\mathbf{ESR}$ should also equal 1. This is due to the fact that the H9K uses two's
complement to represent negative values and that, when subtracting, the actual arithmetic operation
perfomed is $0 + (\bar{0} + 1)$.

	\section{HAL9000 Emulator Code}
	\begin{lstlisting}[style=customasm, caption={HAL9000 emulator code}, label={code:h9kemulator}]
*-----------------------------------------------------------
* Title      : PRAFIN23
* Written by : Serafi Nebot Ginard
* Date       : 19/05/2023
* Description: Emulador de la HAL9000
*-----------------------------------------------------------
	ORG $1000
EMEM:	
	DC.W $E082,$E09B,$E0B4,$E01D,$2020,$C006,$2031,$C017,$F160
	DC.W $F170,$CE70,$3040,$EFFD,$501E,$4008,$8000,$0001
	DC.W $0001,$0001,$0001,$0001,$0001,$0000,$0000,$0000
EIR:	DC.W 0 ;eregistro de instruccion
EPC:	DC.W 0 ;econtador de programa
ET0:	DC.W 0 ;eregistro T0
ET1:	DC.W 0 ;eregistro T1
EX2:	DC.W 0 ;eregistro X2
EX3:	DC.W 0 ;eregistro X3
EX4:	DC.W 0 ;eregistro X4
EX5:	DC.W 0 ;eregistro X5
EX6:	DC.W 0 ;eregistro X6
EX7:	DC.W 0 ;eregistro X7
ESR:	DC.W 0 ;eregistro de estado (00000000 00000CNZ)

START:
	CLR.W EPC
FETCH:
    ;--- IFETCH: INICIO FETCH
        ;*** En esta seccion debeis introducir el codigo necesario para cargar
        ;*** en el EIR la siguiente instruccion a ejecutar, indicada por el EPC,
	    ;*** y dejar listo el EPC para que apunte a la siguiente instruccion

		; ESCRIBID VUESTRO CODIGO AQUI
	MOVE.W EPC, D1
	MULU #2, D1 ; multiply address by 2 (each position contains 2 Bytes)
	MOVEA.W D1, A0
	MOVE.W EMEM(A0), EIR ; load current instruction to EIR
	ADDQ.W #1, EPC ; increase EPC by 1 after fetch
	;--- FFETCH: FIN FETCH

    ;--- IBRDECOD: INICIO SALTO A DECOD
        ;*** En esta seccion debeis preparar la pila para llamar a la subrutina
        ;*** DECOD, llamar a la subrutina, y vaciar la pila correctamente,
        ;*** almacenando el resultado de la decodificacion en D1

		; ESCRIBID VUESTRO CODIGO AQUI
	SUBQ.W #2, SP ; reserve 1 word for instruction id
	MOVE.W EIR, -(SP) ; pass instruction to decode
	JSR DECOD
	ADDQ.W #2, SP ; pop instruction to decode from stack
	MOVE.W (SP)+, D1 ; retrieve instruction's id
	;--- FBRDECOD: FIN SALTO A DECOD

    ;--- IBREXEC: INICIO SALTO A FASE DE EJECUCION
        ;*** Esta seccion se usa para saltar a la fase de ejecucion
        ;*** NO HACE FALTA MODIFICARLA
	; multiply instruction index by 6 (each jump instruction occuppies 6
	; bytes)
	MULU #6, D1
	MOVEA.L D1, A1
	JMP JMPLIST(A1)
JMPLIST:
	JMP ELOA
	JMP ESTO
	JMP ELOIP
	JMP ESTIP
	JMP EGOI
	JMP EGOZ
	JMP EGON
	JMP EEXIT
	JMP ECOPY
	JMP EADD
	JMP ESUB
	JMP EAND
	JMP ESET
	JMP EADQ
	JMP ELSH
	;--- FBREXEC: FIN SALTO A FASE DE EJECUCION

    ;--- IEXEC: INICIO EJECUCION
        ;*** En esta seccion debeis implementar la ejecucion de cada einstr.
	
	; ESCRIBID EN CADA ETIQUETA LA FASE DE EJECUCION DE CADA INSTRUCCION

	; NOTE on the following list of EINSTRUCTIONS implementations
	;   - RGET and RSET subroutines are used to get or set eregisters
	;   - EMEM is accessed with indexed mode
	;       (indexes are multiplied by 2 as each ememory cell contains 2
	;        Bytes)
	;   - AND instruction is used in instead of BTST as the former allows
	;       all possible sizes and the latter only allows byte and longword
	;   - FLAGS subroutine is used to update specific flags
	;   - Arithmetic operations are performed with longword size as the
	;       result will contain the carry bit (passed to FLAGS subroutine)
ELOA:
	CLR.L D2

	; load M operand to D2
	MOVE.W EIR, D2
	LSR.W #1, D2
	ANDI.W #%11111111, D2

	; load Ti operand to D3
	MOVE.W EIR, D3
	ANDI.W #%1, D3

	; load value at address M
	MULU.W #2, D2
	MOVEA.L D2, A2
	MOVE.W EMEM(A2), D2

	; set Ti to the value at address M (Ti <- [M])
	MOVE.W D3, -(SP)
	MOVE.W D2, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; update NZ falgs from ESR
	MOVE.W #%011, -(SP)
	MOVE.L D2, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
ESTO:
	CLR.L D3

	; load Ti operand to D2
	MOVE.W EIR, D2
	ANDI.W #%1, D2

	; load M operand to D3
	MOVE.W EIR, D3
	LSR.W #1, D3
	ANDI.W #%11111111, D3

	; get value of Ti
	MOVE.W D2, -(SP)
	JSR RGET
	MOVE.W (SP)+, D2

	; store value of Ti to address M (M <- [Ti])
	MULU.W #2, D3
	MOVEA.L D3, A3
	MOVE.W D2, EMEM(A3)

	JMP FETCH
ELOIP:
	CLR.L D4

	; load Xb operand to D2
	MOVE.W EIR, D2
	LSR.W #4, D2
	ANDI.W #%111, D2

	; load Ti operand to D3
	MOVE.W EIR, D3
	ANDI.W #%1, D3

	; get value of Xb
	MOVE.W D2, -(SP)
	JSR RGET
	MOVE.W (SP)+, D4

	; set value at address Xb to Ti (Ti <- [[Xb]])
	MOVE.W D3, -(SP)
	MOVE.L D4, D5
	MULU.W #2, D5
	MOVEA.L D5, A2
	MOVE.W EMEM(A2), -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; set Xb to Xb + 1 (Xb <- [Xb] + 1)
	ADDQ.W #1, D4
	MOVE.W D2, -(SP)
	MOVE.W D4, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; set flags NZ from ESR
	MOVE.W #%011, -(SP)
	MOVE.L D4, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
ESTIP:
	CLR.L D4

	; load Ti operand to D2
	MOVE.W EIR, D2
	ANDI.W #%1, D2

	; load Xb operand to D3
	MOVE.W EIR, D3
	LSR.W #4, D3
	ANDI.W #%111, D3

	; get value of Ti
	MOVE.W D2, -(SP)
	JSR RGET
	MOVE.W (SP)+, D2

	; get value of Xb
	MOVE.W D3, -(SP)
	JSR RGET
	MOVE.W (SP)+, D4

	; load value at address Xb
	MOVE.L D4, D5
	MULU.W #2, D5
	MOVEA.L D5, A4
	MOVE.W D2, EMEM(A4)

	; set Xb to Xb + 1 (Xb <- [Xb] + 1)
	ADDQ.W #1, D4
	MOVE.W D3, -(SP)
	MOVE.W D4, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	JMP FETCH
EGOI:
	; load M operand to D2
	MOVE.W EIR, D2
	LSR.W #1, D2
	ANDI.W #%11111111, D2

	; set EPC to M (EPC <- M)
	MOVE.W D2, EPC

	JMP FETCH
EGOZ:
	; check Z flag from ESR
	MOVE.W ESR, D2
	ANDI.W #%1, D2
	BEQ FETCH ; Z = 0 -> end instruction execution
	JMP EGOI ; unconditional jump
EGON:
	; check N flag from ESR
	MOVE.W ESR, D2
	MOVE.W ESR, D2
	ANDI.W #%10, D2
	BEQ FETCH ; N = 0 -> end instruction execution
	JMP EGOI ; unconditional jump
EEXIT:
	SIMHALT
ECOPY:
	CLR.L D2

	; load Rb operand to D2
	MOVE.W EIR, D2
	LSR.W #4, D2
	ANDI.W #%111, D2

	; load Rc operand to D3
	MOVE.W EIR, D3
	ANDI.W #%111, D3

	; get value of Rb
	MOVE.W D2, -(SP)
	JSR RGET
	MOVE.W (SP)+, D2

	; set Rc to the value of Rb (Rc <- [Rb])
	MOVE.W D3, -(SP)
	MOVE.W D2, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; update NZ flags from ESR
	MOVE.W #%011, -(SP)
	MOVE.L D2, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
EADD:
	CLR.L D2
	CLR.L D3

	; load Ra operand to D2
	MOVE.W EIR, D2
	LSR.W #8, D2
	ANDI.W #%111, D2

	; load Rb operand to D3
	MOVE.W EIR, D3
	LSR.W #4, D3
	ANDI.W #%111, D3

	; load Rc operand to D4
	MOVE.W EIR, D4
	ANDI.W #%111, D4

	; get value of Ra
	MOVE.W D2, -(SP)
	JSR RGET
	MOVE.W (SP)+, D2

	; get value of Rb
	MOVE.W D3, -(SP)
	JSR RGET
	MOVE.W (SP)+, D3

	; set Rc to Rb + Ra (Rc <- [Rb] + [Ra])
	ADD.L D2, D3
	MOVE.W D4, -(SP)
	MOVE.W D3, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; update CNZ flags from ESR
	MOVE.W #%111, -(SP)
	MOVE.L D3, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
ESUB:
	CLR.L D2
	CLR.L D3

	; load Ra operand to D2
	MOVE.W EIR, D2
	LSR.W #8, D2
	ANDI.W #%111, D2

	; load Rb operand to D3
	MOVE.W EIR, D3
	LSR.W #4, D3
	ANDI.W #%111, D3

	; load Rc operand to D4
	MOVE.W EIR, D4
	ANDI.W #%111, D4

	; get value of Ra
	MOVE.W D2, -(SP)
	JSR RGET
	MOVE.W (SP)+, D2

	; get value of Rb
	MOVE.W D3, -(SP)
	JSR RGET
	MOVE.W (SP)+, D3

	; subtract Ra to Rb (Rb + (Ra' + 1))
	NOT.W D2
	ADDQ.L #1, D2
	ADD.L D2, D3

	; set Rc to Rb - Ra
	MOVE.W D4, -(SP)
	MOVE.W D3, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; update CNZ flags from ESR
	MOVE.W #%111, -(SP)
	MOVE.L D3, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
EAND:
	CLR.L D3

	; load Ra operand to D2
	MOVE.W EIR, D2
	LSR.W #8, D2
	ANDI.W #%111, D2

	; load Rb operand to D3
	MOVE.W EIR, D3
	LSR.W #4, D3
	ANDI.W #%111, D3

	; load Rc operand to D4
	MOVE.W EIR, D4
	ANDI.W #%111, D4

	; get value of Ra
	MOVE.W D2, -(SP)
	JSR RGET
	MOVE.W (SP)+, D2

	; get value of Rb
	MOVE.W D3, -(SP)
	JSR RGET
	MOVE.W (SP)+, D3

	; set Rc to Rb and Ra (Rc <- [Rb] and [Rc])
	AND.W D2, D3
	MOVE.W D4, -(SP)
	MOVE.W D3, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; update flags CNZ from ESR
	MOVE.W #%111, -(SP)
	MOVE.L D3, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
ESET:
	CLR.L D2

	; load k operand to D2
	MOVE.W EIR, D2
	LSR.W #3, D2
	ANDI.W #%11111111, D2
	EXT.W D2 ; sign extend form byte to word size

	; load Rc operand to D3
	MOVE.W EIR, D3
	ANDI.W #%111, D3

	; set Rc to k (Rc <- k)
	MOVE.W D3, -(SP)
	MOVE.W D2, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; update flags NZ from ESR
	MOVE.W #%011, -(SP)
	MOVE.L D2, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
EADQ:
	CLR.L D2
	CLR.L D4

	; load k operand to D2
	MOVE.W EIR, D2
	LSR.W #3, D2
	ANDI.W #%11111111, D2
	EXT.W D2 ; sign extend from byte to word size

	; load Rc operand to D3
	MOVE.W EIR, D3
	ANDI.W #%111, D3

	; get value of Rc
	MOVE.W D3, -(SP)
	JSR RGET
	MOVE.W (SP)+, D4

	; add k to the value of Rc
	ADD.L D2, D4
	;  set Rc to Rc + k (Rc <- [Rc] + k)
	MOVE.W D3, -(SP)
	MOVE.W D4, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; update CNZ flags from ESR
	MOVE.W #%111, -(SP)
	MOVE.L D4, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
ELSH:
	CLR.L D3
	CLR.L D5

	; load p operand to D2
	MOVE.W EIR, D2
	LSR.W #8, D2
	ANDI.W #%111, D2
	; if p = 0 -> p = 8
	BNE ELSH_N8
	ORI.W #%1000, D2
ELSH_N8:
	; load Rb operand to D3
	MOVE.W EIR, D3
	LSR.W #4, D3
	ANDI.W #%111, D3

	; get value of Rb
	MOVE.W D3, -(SP)
	JSR RGET
	MOVE.W (SP)+, D5

	; load n operand to D4
	MOVE.W EIR, D4
	ANDI.W #1, D4
	; check value of n
	BNE ELSH_N0
	LSL.L D2, D5 ; n = 0 -> left shift
	JMP ELSH_END
ELSH_N0:
	LSR.L D2, D5 ; n = 1 -> right shift
ELSH_END:
	; set Rb to shifted value
	MOVE.W D3, -(SP)
	MOVE.W D5, -(SP)
	JSR RSET
	ADDQ.L #4, SP

	; update CNZ flags from ESR
	MOVE.W #%111, -(SP)
	MOVE.L D5, -(SP)
	JSR FLAGS
	ADDQ.L #6, SP

	JMP FETCH
	;--- FEXEC: FIN EJECUCION

    ;--- ISUBR: INICIO SUBRUTINAS
        ;*** Aqui debeis incluir las subrutinas que necesite vuestra solucion
        ;*** SALVO DECOD, que va en la siguiente seccion

	        ; ESCRIBID VUESTRO CODIGO AQUI

	; ESCRIBID VUESTRO CODIGO AQUI
RGET:
	MOVE.L D0, -(SP)
	MOVE.L A0, -(SP)
	CLR.L D0
	MOVE.W 12(SP), D0 ; load register number

	; multiply D0 by 10 (each register instruction batch occuppies 10 Bytes)
	MULU #10, D0
	MOVEA.L D0, A0
	JMP RGLIST(A0) ; jump to corresponding register number
RGLIST:
RGT0:
	MOVE.W ET0, D0
	JMP RG_END
RGT1:
	MOVE.W ET1, D0
	JMP RG_END
RGX2:
	MOVE.W EX2, D0
	JMP RG_END
RGX3:
	MOVE.W EX3, D0
	JMP RG_END
RGX4:
	MOVE.W EX4, D0
	JMP RG_END
RGX5:
	MOVE.W EX5, D0
	JMP RG_END
RGX6:
	MOVE.W EX6, D0
	JMP RG_END
RGX7:
	MOVE.W EX7, D0
	JMP RG_END
RG_END:
	MOVE.W D0, 12(SP)
	MOVE.L (SP)+, A0
	MOVE.L (SP)+, D0
	RTS

RSET:
	MOVE.L D0, -(SP)
	MOVE.L D1, -(SP)
	MOVE.L A0, -(SP)
	CLR.L D0
	MOVE.W 18(SP), D0 ; load register number
	MOVE.W 16(SP), D1 ; load register value

	; multiply D0 by 10 (each register instruction batch occuppies 10 Bytes)
	MULU #10, D0
	MOVEA.L D0, A0
	JMP RSLIST(A0) ; jump to corresponding register number
RSLIST:
RST0:
	MOVE.W D1, ET0
	JMP RS_END
RST1:
	MOVE.W D1, ET1
	JMP RS_END
RSX2:
	MOVE.W D1, EX2
	JMP RS_END
RSX3:
	MOVE.W D1, EX3
	JMP RS_END
RSX4:
	MOVE.W D1, EX4
	JMP RS_END
RSX5:
	MOVE.W D1, EX5
	JMP RS_END
RSX6:
	MOVE.W D1, EX6
	JMP RS_END
RSX7:
	MOVE.W D1, EX7
	JMP RS_END
RS_END:
	MOVE.L (SP)+, A0
	MOVE.L (SP)+, D1
	MOVE.L (SP)+, D0
	RTS

FLAGS:
	MOVE.L D0, -(SP)
	MOVE.L D1, -(SP)
	MOVE.L D2, -(SP)
	MOVE.L 16(SP), D0 ; load value
	MOVE.W 20(SP), D2 ; load selected flags to update
	MOVE.L D0, D1

	; shift right 14 bits so that negative and carry bits
	; can be OR'ed together with Z flag
	LSR.L #8, D1
	LSR.L #6, D1
	ANDI.W #%110, D1
	; check if value is 0
	ANDI.W #$ffff, D0
	BNE FLAGSNZ
	ORI.W #%001, D1 ; value = 0 -> set Z bit to 1
FLAGSNZ:
	; mask selected flags' values
	AND.W D2, D1
	; negate mask so that selected flags are cleared
	NOT.W D2
	ANDI.W #%111, D2
	AND.W D2, ESR ; clear selected flags
	OR.W D1, ESR ; update selected flags
	MOVE.L (SP)+, D2
	MOVE.L (SP)+, D1
	MOVE.L (SP)+, D0
	RTS
	;--- FSUBR: FIN SUBRUTINAS

    ;--- IDECOD: INICIO DECOD
        ;*** Tras la etiqueta DECOD, debeis implementar la subrutina de
        ;*** decodificacion, que debera ser de libreria, siguiendo la interfaz
        ;*** especificada en el enunciado
DECOD:
	        ; ESCRIBID VUESTRO CODIGO AQUI
	MOVE.L D0, -(SP) ; save current value of D0
	MOVE.W 8(SP), D0 ; load instruction
	BTST.L #15, D0
	BEQ.S DECOD_END ; if bit 15 = 0 jump to end
	LSL.W #1, D0 ; left shift to "normalize" 5 bit opcode to 4 bit opcode
	BTST.L #15, D0
	BNE.S DECOD_END ; if bit 15 = 1 jump to end
	MOVE.W #%0111000000000000, D0 ; if bit 15 = 0 then instruction = EXIT
DECOD_END:
	; shift right the four MSb to the four LSb
	LSR.W #8, D0
	LSR.W #4, D0
	MOVE.W D0, 10(SP) ; save instruction ID to reserved space
	MOVE.L (SP)+, D0 ; restore value of D0
	RTS

	;--- FDECOD: FIN DECOD
	END	START
